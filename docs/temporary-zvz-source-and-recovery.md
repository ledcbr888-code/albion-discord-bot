## Source policy
The original Battleboard integration and automatic recovery are unchanged. If the website is healthy, it continues to own delivery. Only the existing fallback scanner can use AlbionZvZ, after explicit permission and configuration:
- `ALBIONZVZ_PRIMARY_ENABLED=false` (default) = original Official data path.
- `ALBIONZVZ_PRIMARY_ENABLED=true` = try AlbionZvZ Asia before Official, for eligible recent tracked battles. Shared cached list (at most 25 records per 60 seconds), at most 3 uncached detail requests per minute, 5-second timeouts, no redirects. These are conservative local ceilings, NOT a verified provider quota.
- The observed public-browser routes are /api/battles and /api/dev/battle-board/battle. No cookies, credentials, access-control bypass, or private endpoint probing.
- Exact guild ID/name, Asia server, Battle ID, timestamps, participant counts and coherent totals must agree. Incomplete responses go to the original Official detail path; missing weapon equipment continues to use Official events enrichment. No threshold or report deduplication changes.
- HTTP 401/403 disables AlbionZvZ requests for the rest of the process; 429 respects Retry-After with a minimum 10-minute cooldown. Missing/new matches, invalid/failed list, and periodic Official reconciliation every 5 minutes per tracker preserve smaller-fight coverage. This mode is experimental and may not deliver faster than Official. Request primary-provider approval before enabling; the published acceptable-use terms do not establish a guaranteed external-bot API entitlement.
- Both temporary scanner sources now display masked AlbionZvZ Battle ID links, start-of-send delay from actual endTime, and matching main report text. The website may not index very small or newly published battles. Full send-completion timing remains in logs.
- When BOSS BOT Battleboard becomes healthy, its existing runtime preflight/recovery returns delivery to it (subject to existing pending-delivery and single-owner guards). Set the temporary flag to false/omit it on the next approved restart. Keep the latest tracking state; do not roll back database or tracking files. The backup code branch is an emergency option, not the preferred return path.
