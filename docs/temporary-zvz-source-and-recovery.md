## Source policy
The original Battleboard integration and automatic recovery are unchanged. If the website is healthy, it continues to own delivery. Only the existing fallback scanner can use AlbionZvZ, after explicit permission and configuration:
- `ALBIONZVZ_PRIMARY_ENABLED=false` (default) = original Official data path.
- `ALBIONZVZ_PRIMARY_ENABLED=true` = try AlbionZvZ Asia before Official for **every confirmed tracked Battle ID regardless of participant count**. The bot's `/autobattle` guild/player tracking and configured `min_frames` Fame are unchanged; participant count is NEVER a new report threshold.
- The AlbionZvZ list requests `minMass=1` instead of 10, and the adapter accepts fully verified 1–9-player Details. The bot may receive a Battle ID from Official Asia List that is absent from AlbionZvZ List: it still makes one rate-limited direct AlbionZvZ Detail attempt first. If the provider has not indexed that ID (HTTP 404 or no battle), it caches that per-ID absence for 5 minutes and uses Official Asia without opening a site-wide circuit breaker.
- The provider publicly describes 10+ participant coverage for its **Battleboard list**, but the **direct Detail API can still serve smaller IDs**. A one-time real Asia check on **2026-11-21** for **Battle `531162052` (5 players, 3 kills, 224,808 fame)** returned HTTP 200 from both AlbionZvZ Detail and Official Asia Detail. The new adapter validated the unlisted direct AlbionZvZ response. This proves at least this small Battle is available, **not that all small IDs are indexed**. The bot always tries the direct Detail first for Official-discovered IDs; if missing/invalid it falls back to Official. No retries against access denials or scraping alternate pages.
- Shared cached list (at most 25 records per 60 seconds), at most 3 uncached detail requests per minute, 5-second timeouts, no redirects. These are conservative local ceilings, NOT a verified provider quota.
- The observed public-browser routes are /api/battles and /api/dev/battle-board/battle. No cookies, credentials, access-control bypass, or private endpoint probing.
- Exact guild ID/name, Asia server, Battle ID, timestamps, participant counts and coherent totals must agree. The **real 2026-11-21 AlbionZvZ Detail payload does not contain guilds/alliances**, so the adapter reconstructs Guild/Alliance summaries from the exact List guildMasses IDs and explicit Detail player stats. It validates matching per-guild player counts, names, kills and deaths. An 8-Fame total-vs-player variance was observed **identically in Official and AlbionZvZ**, so a tiny bounded variance (at most 100 Fame / 0.005%) is allowed without changing any individual player Fame. Incomplete or materially divergent responses go to the original Official detail path; missing weapon equipment continues to use Official events enrichment. No threshold or report deduplication changes.
- **Non-evasive anti-block safeguards:** all guild trackers and both AlbionZvZ endpoints share one serial request lane with a **minimum 3.5-second spacing** between HTTP requests. Existing single-flight cache keeps List requests at most once per 60 seconds (25 rows), and Detail requests at most 3 new IDs per minute (cached for 120 seconds). This adds a few seconds to some reports in exchange for less burst traffic; it **does not bypass an HTTP 403**, rotate IPs/proxies, solve challenges, or guarantee a zero-403 rate.
- **Circuit breaker:** HTTP 401/403 disables further AlbionZvZ requests until the process restarts; no attempts to defeat a denial. HTTP 429 respects the **longer of Retry-After and progressive exponential cooldown** (starting at 10 minutes, capped at 1 hour, plus up to 10% jitter). HTTP 5xx, timeouts, and invalid schema also back off exponentially (starting at 1 minute, capped at 1 hour). During all cooldowns the Official API path remains enabled. No immediate retries against a denied or throttled host.
## PR #50: per-Battle Detail source diagnostics (read-only logging)
- The log line `[Auto-Battle Detail Source]` now identifies each **attempted** Battle ID, the selected `Source=AlbionZvZ Asia` or `Source=Official Albion API Asia`, `Players`, an explicit `PrimaryReason`, and whether the selected Detail was available. This includes prefetched Battle IDs and skipped Fame-below-threshold fights: no Discord send is needed to see the source decision.
- Expected primary reasons include `PRIMARY_HTTP_200`, `PRIMARY_CACHE_OK`, `HTTP_404`, `HTTP_403`, `HTTP_429`, `HTTP_5XX`, `TIMEOUT`, `NO_BATTLE_DETAIL`, `INVALID_DETAIL`, `NOT_INDEXED_CACHED`, `DETAIL_REQUEST_BUDGET`, `CIRCUIT_DENIED`, `CIRCUIT_COOLDOWN`, and `PRIMARY_DISABLED`. `EVENT_ONLY_OFFICIAL_PROBE` indicates a provisional Events hint still using the existing Official-only path, not a failed AlbionZvZ request.
- The old `[Auto-Battle Latency] ... ผลลัพธ์=เฟมต่ำกว่าเกณฑ์` entry also includes `ข้อมูลรายงาน=` and `ผู้เล่นใน Battle Detail=`. Source selection, Guild/Player tracking, Fame threshold, dedupe, cache and API request budgets, storage, Discord sends, and retry behavior remain unchanged. Diagnostics never print tokens or HTTP auth headers.
- These observations prove which Detail source was used, not whether the Battle met Fame or was delivered; the corresponding result/delivery log still controls that determination. PR #50 does not configure CoalByte Startup Detection or change the live runtime until separately approved for deploy.

- Each successful Auto-Battle report writes safe `AlbionZvZ HTTP Stats` to the CoalByte log (request counts, cache hits, waits, circuit state and per-process 403/429 percentages; no tokens or player-identifying data in metrics). The percentage is **observational** and only meaningful after representative live operation, not a predicted chance of being blocked. Missing/new matches, invalid/failed list, and periodic Official reconciliation every 5 minutes per tracker preserve smaller-fight coverage. This mode is experimental and may not deliver faster than Official. Provider approval for unattended third-party API use remains unverified.
- When a Battle ID has been confirmed in the AlbionZvZ Asia List, the temporary scanner displays a masked AlbionZvZ link. If it is not indexed there (such as a small Official-only fight), it links the same numeric ID to the **official Albion killboard** to avoid a dead third-party URL. Both sources display start-of-send delay from actual endTime and matching report text; full send-completion timing remains in logs.
- When BOSS BOT Battleboard becomes healthy, its existing runtime preflight/recovery returns delivery to it (subject to existing pending-delivery and single-owner guards). Set the temporary flag to false/omit it on the next approved restart. Keep the latest tracking state; do not roll back database or tracking files. The backup code branch is an emergency option, not the preferred return path.
